# 경마지 (racing form) — 방향 문서

경주 전날 오후 6시에 고정 발행하는 무료 웹 경마지 `/form`. 미리 공개한 기준 4개가 각자 ◎○△ 를 고르고,
KRA 데이터로 말 소식을 정리하고, 적중 기록을 첫 호부터 빠짐없이 공개한다.

> - **상태 (2026-11-13)**: 1단계 **PR-1 진행 중** — 문서·테이블(036)·크롤러 코드·메뉴 링크 없는 페이지까지.
>   스케줄을 연결하지 않아 발행은 아직 없고, 사이트 메뉴·검색 색인에도 노출하지 않는다. 진행 기록은 [docs/tasks/0005](../tasks/0005-racing-form.md).
> - **데이터 계약(단일 진실원)**: [docs/spec/racing-form-contract.md](../spec/racing-form-contract.md) — as-of 규칙·기준 r1·말 소식·payload v1·정산·공지·화면 상태. 이 문서와 어긋나면 계약이 맞다.
> - **실제 수치·문구**: [crawler/src/racing_form/definitions.py](../../crawler/src/racing_form/definitions.py) 의 `RULE_SETS["r1"]`. 이 문서의 숫자는 설명용이다.
> - 구현 전에 쓴 방향 문서다. CLI 옵션 이름·라인 번호 같은 세부는 S7(PR-3)에서 코드 기준으로 확정한다. 라인 번호는 2026-11-13 기준.

## ① 요약과 사용자 결정

### 1.1 한눈에

- **무엇** — 경주 전날 18:00 에 고정 발행하는 무료 웹 경마지. 한 호 = (경주일, 경마장).
  1면(경주별 주목마 한 줄·말 소식·기준 성적) → 경주면(기준별 ◎○△·근거·출전마 카드) → 기록 페이지.
- **추천** — 공개 기준 4개(레이팅·최근 성적·거리 적성·기수, 예비 조교사)가 각자 ◎○△ 를 고른다.
  예상을 낸 기준 3개 이상이 고른 말이 **주목마**(경주당 최대 2두). 점수 합산 없음, 근거는 숫자 한 줄.
- **말 소식** — 기존 테이블에서 뽑는 KRA 사실 이벤트(기수 교체·등급 변동·휴양 복귀·데뷔·거리 변화 등). 평가어 금지.
- **책임** — 발행 즉시 동결(추가 전용 테이블 + 트리거 + 해시). 첫 호부터 전부 집계(빗나감·무효·미발행·철회 포함),
  같은 경주의 무작위·경주 후 1번 인기와 비교, 회수율(ROI) 없음, 고지(마권 구매 연령 경마장 만 19세·온라인 만 21세, ☎1336).
- **구현** — 마이그레이션 036(테이블 6), 크롤러 `src/racing_form/` + 잡 2개(발행 매시 정각·정산 :15/:45),
  웹 `/form/**` 5경로. 기존 데이터만 쓰고 KRA 호출·새 env 없음.
- **출시 순서** — PR-1(문서·코드·빈 테이블·메뉴 링크 없는 페이지) → 사용자의 prod 읽기 전용 감사·과거 시험(G1)
  → PR-2 스케줄 연결(목 18:00 전) → 첫 호 확인 → PR-3 메뉴·색인 연결 (⑩).

### 1.2 배경

- 2026-11-07 자체 점수(mal지수 MSF — "일단 빼자")와 네이버 뉴스(노이즈)를 제거했다. KRA 공식 레이팅은 유지.
- 그래서 새 경마지는 **블랙박스 점수 대신 '근거가 보이는' 주목마**, **KRA 데이터 이벤트 기반 말 소식**으로 간다.
- 타깃은 50대+ 고령 팬, 모바일 우세, 가독성이 wedge ([DESIGN.md](../../DESIGN.md)).

### 1.4 현황 — 재사용하는 것과 없는 것 (2026-11 코드 기준)

**재사용**
- 출전표 `race_entries` — 출전번호·기수·조교사·연령·성별·경주 시점 레이팅 `rating`, 부담중량은 `raw->>'wgBudam'`.
  공표 D−3~2, `mal.sync_race_entries` 3시간 주기 수집.
- 결과 `race_results` — 착순·기록·마체중·착차 `raw->>'differ'`·경주 시점 레이팅 `raw->>'hrRating'`.
  **upsert 로 덮어써 이력이 없다** (`crawler/src/jobs/sync_races.py:36-48`). 과거 시험 입력으로는 충분.
- 레이팅 `horse_ratings`(토 07:30 주간 스냅샷, 2026-04-23~) · 등급변동 `horse_rank_changes`(매일 06:35) ·
  기수변경 `jockey_changes`(매일 06:25 1회) · 대상경주 `race_plans`.
- 화면 부품 — `/races` 출전표(경주 전엔 race_entries 폴백), `RankBadge`·`RecentFormStrip`·`GateNum`·`RatingSparkline`.

**없음 (1단계에서 다루지 않음)**
- 경주 전 배당·인기, 날씨 예보, 조교·진료·출전취소·장구, 경주 전 마체중(출전표 API 에 없음),
  새 경주의 코너·전개 데이터(구간기록 수집 2026-11 중단).
- 경주 시점(as-of) 계산 — `getHorseCompareSummaries`·`getHorseFormBreakdown` 은 날짜 컷이 없어 지난 경주 카드에
  이후 성적이 섞인다. 경마지는 이 함수들을 쓰지 않는다 (`getRecentFinishesBulk` 는 as-of 안전).
- 면책·연령 고지 — 사이트 전체에 사행·19세·1336 문구 0건 ([CRITIQUE.md](../../CRITIQUE.md) C-1 미해결).
  추천 기능은 이 리스크를 키우므로 경마지에 고지를 새로 만든다.

**설계 제약 — 동결이 필요한 이유**
- `race_entries`·`race_results` 는 덮어쓰고 이력이 없다 → **발행 시점 JSON 스냅샷 저장만이 고정판을 재현**한다.
- 과거 성적 컷은 `race_date < H(=D−1)` 하나로 통일한다. 동결 시각(D−1 18:00)에 D−1 경주는 진행 중·정정 전이고,
  같은 날 앞 경주 결과도 빠지므로 한 호가 한 벌로 고정된다.
- 함정 — 기수·조교사는 이름 매칭(jk_no·tr_no 미적재) · meet 표기 '부경' vs '부산경남' · `race_dividends.horse_no`
  에는 출전번호 · 출전취소·이동마가 `race_entries` 에 남음(stale) · `rank` NULL/0 · 실제 기수 = 기수변경 반영 ·
  부경 발주 시각은 당일 06:05 이후에야 채워짐. 처리 규칙은 계약 §1.

### 2.2 편성과 공표 일정 (2026)

- 서울 토·일 · 부경 금·일 · 제주 금·토 · **영천 9/13~12/6 매주 일 6경주**.
- 출전신청 수 10~11시 → 출전표 수 오후 공표 → 금요 경주는 D−2, 일요 경주는 D−4 에 출전마가 확정된다.
- 마체중은 출발 50분 전에야 나온다 — 전날 발행하는 경마지는 마체중을 담을 수 없다.

### 2.3 예상지의 문법 (콘텐츠)

- **사실층** — 출마표·전적·조교 횟수·장구 +/−·특이사항.
- **판단층** — 축마/입상 후보/도전마/복병. 기호 범례는 매체마다 다르다. 근거 = 단독 선행·추입·병행 훈련·기수 교체.
- 판단 방법은 공개하지 않고(예상위원 판단), 적중 기록은 맞힌 사례 홍보 외에는 내지 않는다.

### 2.4 독자

- **KRA 2024 조사(4,900명)**: 60대 44.9% · 50대 31.5% · 70대 이상 12.0% · 남성 85.2%.
- 온라인 마권(더비온, 만 21세 이상) 매출 비중 2026년 1~9월 32.2%, 온라인 회원도 50대 이상이 81.9%
  → **고령층이 모바일로 옮겨 가는 중**이고 장외발매소는 줄고 있다.

### 2.5 법적 경계 (법률 자문 아님)

- 근거는 한국마사회법 제48조 등. 예상 정보 제공 자체는 합법이라는 것이 마사회 답변이다.
- 금지·위험: 적중 보상·환전 가능한 포인트, 마권 구매 대행·알선·구매 링크, 배당·경주 영상 재전송,
  '마사회 공식' 허위 표시, 미성년 노출. 마권 구매 연령은 현장 만 19세 · 온라인 만 21세.
- 경마지의 대응: 구매처·배당·영상 링크 없음, ROI 없음, 댓글 없음, 고지 신설(④·⑦). 최종 고지 문구·기호·
  청소년유해매체물 해당 여부·AdSense 정책·data.go.kr 이용조건은 **G1 법률 검토** 항목(⑩).

### 2.6 시사점 — 경마지의 차별점

사실 정보는 KRA 가 무료로 공개한다. 그러니 차별점은 사실을 다시 파는 데 있지 않다.
1. 무료 + 읽기 쉬움 (고령 독자)
2. 근거가 보이는 판단
3. 적중 기록 공개 (국내 예상지에 없음)
4. 말 소식 정리 (변경·복귀·등급 등)

### 4.2 발행 단위와 일정 (KST)

- 한 호 = (경주일 D, 경마장). 보통 주 6호 — 금 부경·제주 / 토 서울·제주 / 일 서울·부경.
  대상은 요일이 아니라 `races ∩ race_entries`(Q0 달력, D ∈ [오늘−7, 오늘+7])로 정한다.
- **과거 성적 기준 H = D−1** (`race_results.race_date < H`). 실전·늦은 발행·과거 시험 모두 같다.

| 시각 | 동작 |
|---|---|
| D−1 18:00 | 발행 = 동결. 발행 잡은 매시 정각 + **기동 직후 1회** (`next_run_time`) |
| D−1 19:00 ~ D 07:00 | 미발행 호를 매시 재시도. freeze + 60분을 넘겨 발행하면 "늦게 발행" 표기 |
| 발행 창 `[freeze_at, deadline_at)` | 반열린 구간. deadline = min(D 08:00, 첫 발주 − 60분; 모르면 08:00). 판정은 분 단위로 자른 예약 시각, `published_at` 은 실제 시각 |
| D 08:00 실행 | 출전표가 있는데 발행본이 없으면 `missed` 공지 1건 + 잡 실패 1회 (발행과 같은 advisory lock 안에서 재확인) |
| D 10:15 ~ 23:45 (:15·:45) | 정산 잡의 잠정 정산 |
| D+1 13:00 | 정산 확정 (이후 불변). 확정 뒤 KRA 결과(착순·상태)가 바뀌면 `result_changed` 공지 + 잡 실패 1회, 자동 수정 없음. 단승 배당만 달라지면(확정 뒤 늦게 들어온 배당 포함) 공지·실패 없이 로그만 — 확정 정산 그대로 |
| D+7 | 결과가 끝내 없으면 경주 무효 확정 |

- D 결과가 하나라도 있으면 발행하지 않는다.
- 같은 (D, 경마장, 사유)의 발행 실패는 첫 1회만 잡 실패로 올리고, 이후는 경고 + 내부 공지(dedup)로 남긴다
  → 밤새 매시 알림이 울리지 않는다.
- 한 호는 한 벌이다 — 일본식 제2판·가판이 없다 (D3).
- 다루는 경마장은 서울·부경·제주. 출전표 수집이 금·토·일·meet 1~3 으로 고정돼 있어
  (`crawler/src/jobs/sync_race_entries.py:101-108`, `:119`) 영천·공휴일 경주는 호가 생기지 않는다
  → 허브·FAQ 에 "다루는 경마장: 서울·부경·제주 (영천·공휴일 경주는 아직 다루지 않습니다)". 수집 확장은 ⑪ 11.3.
- 배포가 18:00 발행과 겹치지 않게 하는 규칙은 ⑨ 9.5.

### 5.1 공통 정의

- **as-of** — 이력은 `race_results.race_date < H` 만. SQL 조건 + Python `assert_strictly_before` 로 이중 차단.
  당일 입력(출전표·기수변경·등급변동·마스터)은 발행 시점 DB 상태 그대로 읽는다. `fetched_at` 필터는 쓰지 않는다
  (기본값이 DB `now()` 라 e2e 가짜 시계와 어긋남).
- **출주 분류** (모든 이력 집계 공통) — `rank ≥ 1` 은 출주. rank NULL/0 이고 기록 > 0 이면 출주로 세되 입상 아님
  (화면 "순위 없음"). 둘 다 없으면 미출주로 이력에서 뺀다. 감사 ① 결과를 보고 r1 에 사전 등록한다 (5.7).
- **활성 출전마** — race_entries(D, meet) 에서
  ① stale 제외: 그 (D, meet) 의 최신 배치 시각(`MAX(updated_at)`)보다 30분 넘게 오래된 행. 한 경주에서 절반 넘게
  빠지면 빼지 않고 경고 ② 같은 날 두 경주에 있으면 최신 행 하나 ③ horse_no 없음·meet '알수없음' 제외,
  출전번호(chul_no) 없는 행도 제외하고 경고 (정렬·동점·화면의 기준값이라).
- **실제 기수** — `btrim(COALESCE(jc.jk_name_after, e.jockey_name))`. jockey_changes 는 meet 없이
  (race_date, race_no, horse_no) 로 LATERAL 최신 1건 (UNIQUE 에 원문 meet 가 있어 중복 위험, `020_jockey_changes.sql:36`).
- **거리** — `COALESCE(races.distance, raw rcDist)` 를 Python 이 파싱, 800~3000m 만 인정.
  **레이팅** — `race_entries.rating`, 없으면 raw `hrRating` 정수 파싱, 0 이하는 미평가.
- **소수 출전** — 활성 N < 5 이면 모든 기준이 "예상 안 함 — 출전 N두".
- form·course 는 그 조건에서 3착 이내가 1번 이상 있는 말만 고른다. 마지막 동점은 출전번호가 작은 말.
- 비율은 정수 연산 `(100·w + n//2)//n`, 비교는 정수 교차곱. payload 에 float 없음.

### 5.2 기준

| key · 이름 | 입력·기간 | 자격 | 예상 안 함 | 정렬 → 동점 | 근거 예 |
|---|---|---|---|---|---|
| `rating` 레이팅 | 출전표 레이팅 | > 0 | 자격 < max(3, ⌈N/2⌉) | 높은 순 → 번호 | "레이팅 68 · 출전 12두 중 1위" |
| `form` 최근 성적 | 출주 [H−365, H) 최근 3전 | 2전 이상 | 자격 < max(3, ⌈N/2⌉) 또는 3착 이내 말 0 | 3착 이내 수↓ → 1착 수↓ → 직전 착순↑ → 평균 착순↑ → 번호 | "최근 3전 4착→2착→1착 (3착 이내 2번)" |
| `course` 거리 적성 | 같은 경마장·같은 거리 통산 (< H) | 3전 이상 | 자격 < 3, 거리 모름, 3착 이내 말 0 | 3착 이내율↓ → 횟수↓ → 1착↓ → 번호 | "서울 1200m 6번 중 3착 이내 4번 (1착 2번)" |
| `jockey` 기수 | 실제 기수, 같은 경마장 [H−90, H) | 20기승 이상, 동명이인 아님 | 자격 < 3 | 승률↓ → 3착 이내율↓ → 기승 수↓ → 번호 | "김기수 기수 · 최근 90일 서울 84번 중 15승 (승률 18%)" |
| (예비) `trainer` 조교사 | 같은 경마장 [H−90, H), btrim 이름 | 20출주 이상 | 자격 < 3 | 승률↓ → 3착 이내율↓ → 출주 수↓ → 번호 | "박조교 조교사 · 최근 90일 서울 40번 중 6승 (승률 15%)" |

- 상위 3두에 ◎○△. 자격 있는 말이 3두 미만이면 있는 만큼만 표시한다.
- 기수·조교사 집계(Q3)는 **이름 하나로** 묶는다. 동명이인 = 같은 경마장·`race_date < H` 에서
  `COUNT(DISTINCT NULLIF(ltrim(btrim(raw->>'jkNo'),'0'),'')) ≥ 2` (NULL 제외, 앞자리 0 정규화) → 그 기수는 제외.
- '예상 안 함' 문구에는 숫자를 넣는다 — "레이팅이 있는 말이 {e}두뿐 (최소 {m}두)" · "최근 1년 2번 이상 뛴 말이 {e}두뿐" ·
  "이 경마장·거리에서 3번 이상 뛴 말이 {e}두뿐" · "거리 정보 없음" · "최근 90일 이 경마장에서 20번 이상 탄 기수의 말이 {e}두뿐".
- 근거는 사실·숫자만, 비율엔 분모. 글리프·금지어는 테스트로 막는다
  ([forbidden_words.json](../../crawler/src/racing_form/data/forbidden_words.json), 웹과 공유).
- `web/src/lib/horse_comment.ts` 는 재사용하지 않는다 ("0승인데 선호 거리" 결함, `:60-65`).
- 예비 `trainer` 는 화면·발행에 없다. 과거 시험에서만 함께 평가해 미달 기준의 대체 후보로 쓴다 (5.6).

### 5.3 종합 주목마

- A = 예상을 낸 (발행) 기준 수, v = 그 말에 ◎○△ 중 하나라도 준 기준 수. **A ≥ 3 이고 v ≥ 3**, 경주당 최대 2두.
  정렬 v↓ → ◎ 수↓ → ○ 수↓ → 번호.
- 문구의 분모는 항상 A — "예상을 낸 기준 3개가 모두 고름" / "예상을 낸 기준 4개 중 3개가 고름".
  근거 = 고른 기준들의 근거 중 (기호 등급 → 고정 순서) 상위 2개.
- 해당 말이 없으면 "혼전 — 기준마다 고른 말이 다릅니다", A < 3 이면
  "주목마 없음 — 기준 3개 이상이 예상해야 고릅니다 (이번엔 {A}개)".
- 저장은 `rule_key='consensus'`, mark 1·2, votes. **주목마 지표는 mark 1 만**으로 센다.

### 5.4 정산·무효 (보수적 기본값 — 감사 뒤 사전 등록)

- 발행 전에 명단에서 빠진 말은 대상이 아니다.
- 발행 후 **결과 행이 없음 → 무효** (분모에서 빼고 기준별 무효 수 공개).
  **결과 행이 있음 → rank·기록과 무관하게 순위 밖이면 빗나감** (주행중지·낙마·실격 포함;
  rank 는 `stOrd or ord`, rcTime "-" 는 NULL — `crawler/src/clients/race_result.py:80, 111`).
  감사 ①에서 raw 표식으로 '출전취소'가 구분될 때만 그 표식을 무효로 좁게 완화한다.
- 결과 행 < 발행 명단 50% → 대기. 결과 행이 전부 rank NULL 이고 D+1 12:30 이 지나면 → 경주 무효.
  D+7 까지 결과가 없으면 → 경주 무효.
- 동착은 winners·placed 배열에 모두 넣고, 하나만 맞혀도 적중. 명단에 없던 출주마는 `extra_starters`(stale 품질 지표).
  주목마가 무효가 돼도 다시 계산하지 않는다.

### 5.5 버전 고정

- `definitions.py` 의 **`RULE_SETS` 레지스트리** (r1, 이후 r2 … 영구 보관) — 기간·임계값·정렬·문구·소식 임계값·정산 정책.
- 정의 해시 = Python 정렬 JSON(`sort_keys`, 고정 separators, `ensure_ascii=False`)의 SHA-256. SQL 로 재계산하지 않는다.
  pytest 가 해시 값을 핀으로 고정한다 → 수치를 바꾸면 버전을 올려야 테스트가 통과한다.
- `ensure_rule_set` 은 **발행 잡만 호출**한다. 행이 없으면 등록, 해시가 다르면 발행 거부 + 잡 실패.
  golden 20경주 conformance(`crawler/tests/fixtures/racing_form/golden_r1.json`)로 해시가 못 잡는 로직 변경도 막는다.
- 발행본엔 `rules_version`, 픽엔 `rule_version`. r2 는 새로 쌓고 과거 호를 소급 재채점하지 않으며,
  `/form/record` 에 변경 이력을 싣는다.
- r1 은 prod 에 처음 등록되기 전(= PR-2 첫 발행 잡 실행 전)까지만 고칠 수 있다 — 감사 뒤 사전 등록(PR-1b)이 그 창이다.
  등록 뒤 수치 변경은 r2.

### 5.6 과거 시험과 출시 게이트 (사전 등록)

- **기간** — dev 2025-01-01~12-31, holdout 2026-01-01~10-31 (워밍업 365일은 dev 이전 데이터).
  감사 ⑥에서 보유 기간이 모자라면 **결과를 보기 전에** dev 만 줄인다.
- **입력** — Q1b = 결과표 기반 명단(출주: rank ≥ 1 또는 기록 > 0, 실제 기수·부담·hrRating).
  `build_edition(mode=backtest)`·settle 과 같은 코드. 픽만 평가하고(소식은 Q4·Q5 가 현재 테이블이라 as-of 불가),
  마스터 기반 가드는 끈다.
- **dev** — 버그 수정만, 파라미터 변경은 최대 1회(문서화) → 후보 정의(4 + 예비) 해시 고정.
- **holdout** — 후보 해시당 1회. `--label holdout` 은 결과 행을 먼저 INSERT 한 뒤 출력하고, 행이 이미 있으면 계산을
  거부한다 (부분 UNIQUE). 계산 중 한 호라도 실패하면(일시적 DB 오류 포함) 그 자리에서 멈추고 저장도 출력도 하지
  않는다 — 1회를 쓰지 않았으니 원인을 고친 뒤 다시 실행한다 (저장된 holdout 은 늘 오류 0).
- **통과 조건**
  1. 결정성·as-of 테스트
  2. 오류 0, 호당 5초 미만, 1년치 10분 미만
  3. 참여율 rating·form·jockey 70% 이상, course 40% 이상
  4. 기준별 ◎ 1착률 > 같은 경주 무작위 기대치 (◎ n ≥ 300)
  5. 감사 ③ 출전표 rating ↔ 결과 hrRating 일치율 95% 이상 (미달이면 rating 의 시험 수치는 게이트에서 빼고 G1 에서 판단)
- **미달 처리 (사전 등록)** — 4개 중 1개 미달 → 예비로 대체 (대체 조합의 주목마 지표도 같은 holdout 보고서에 미리 계산).
  2개 이상 미달이거나 예비도 미달 → **출시 보류, G1 사용자 결정**. 미달 기준은 고치지 않고 r2 후보로 공개.
- 1번 인기를 이기는 것은 조건이 아니다 (공개만). 기준 사이 일치율 행렬을 보고서에 싣는다.

prod 읽기 전용 감사(⑨ 9.7) 결과와 그에 따른 r1 결정을 여기에 남긴다. 결과를 보기 전의 기본값은 위 5.1·5.4.

- 말 배지는 최대 3개 + `<details>`. 우선순위: 기수 교체 > 등급 변동 > 복귀·데뷔 > 처음 탐 > 거리 > 부담 > 레이팅 >

## ⑦ 적중 공개

### 7.1 판정

- 1착 적중 = winners 에 포함, 3착 이내 = placed 에 포함, 무효 = non_starters·race_void, 나머지는 빗나감.
- 집계는 확정분(`is_final`, D+1 13:00 이후)만. 철회해도 포함한다 (예외 없음).
- 미발행·쉼은 호 수로 공개하고, 확정 뒤 결과 변경(`result_changed`)도 기록 페이지에 공개한다.

### 7.2 지표

- 기준 × 기호 — ◎ 1착률 · ◎ 3착 이내율 · ○△ 3착 이내율 · ◎○△ 중 1착마 포함률 · 참여율 · 무효 수.
- 주목마(1순위) — 1착률 · 3착 이내율 · 선정률.
- 기록 페이지에만 ◎ 평균 인기 순위.

### 7.3 비교 기준 (같은 경주 집합)

- **무작위** = Σ(1착 두수 / 출주 두수), Σ(3착 이내 두수 / 출주 두수) (동착 반영).
- **경주 후 1번 인기** = 확정 단승 배당이 가장 낮은 말 (동률이면 모두, `race_dividends.horse_no` 는 출전번호 → 정수 매핑).
  꼬리표 "확정 배당 기준 — 발행 때는 알 수 없던 정보". 배당 숫자는 보이지 않는다. 배당 없는 경주는 이 비교에서만 빼고
  커버리지를 표기한다.
- 고정 문구: "적중률은 수익을 뜻하지 않습니다. 인기 많은 말일수록 배당이 낮습니다."

### 7.4 실전 vs 과거 시험

- 실전은 첫 발행호부터 전부 집계한다. 시범 운영은 비공개 dry-run 만 한다.
- 과거 시험은 `/form/record` 의 별도 섹션 "과거 데이터로 시험(참고)" — 유리한 조건을 명시한다
  (무효 0, 실제 기수·부담, 정정이 끝난 결과, 결과표 레이팅 — 일치율 n%).
- 실전과 합산하지 않고, 실전이 100경주를 넘으면 접어 둔다. 흐린 표현은 투명도 대신 muted 토큰 + 라벨 (DESIGN.md Color 절).

### 7.5 표본 표기

- 항상 분수와 함께 — "19/80 (24%)".
- n < 30 → "경주 수가 30 미만이라 %는 아직 내지 않습니다". n < 100 → "경주 수가 적어 숫자가 크게 흔들립니다".
  흔들림 폭(Wilson)은 `<details>` 안에만.
- 기준은 고정 순서, '최고 기준' 강조 없음. 무작위 대비 차이는 기록 페이지 별도 열에 ▲▼+색.

### 7.6 회수율(ROI)을 내지 않는 이유

화면·DB·CLI 어디서도 계산하지 않는다.
- 구매 권유로 읽힌다 (한국마사회법 맥락 — 법률 자문 아님).
- 고령 독자의 손실 추격 위험.
- 확정 배당은 발행 시점에 모르는 값이다.
- 배당을 가공해 보이면 재전송에 가깝다.

FAQ: "회수율은 일부러 공개하지 않습니다 — 베팅 권유가 아닙니다".

### 7.7 노출 위치

- 1면: 실전 축약 (④ 4.5-6) · 경주면: 기준 라벨 `<details>` · 허브: 한 줄.
- `/form/record`: 전체 — 경마장·기간 필터, 과거 시험, 기준 정의, 발행 이력(호 수·늦게 발행·미발행 사유·철회·정정·쉼),
  FAQ ("왜 30%도 안 되나요? → 12두 경주에서 무작위 1착은 약 8%").

### 8.2 보호 장치와 그 한계

- 트리거 12개(`trg_rf_%`): 추가 전용 5 + 정산 가드 1 + 여섯 테이블 TRUNCATE 거부 6. 전부 `ENABLE ALWAYS` —
  `session_replication_role=replica` 로도 꺼지지 않는다. TRUNCATE 는 세션 GUC `mal.racing_form_allow_truncate='on'`
  일 때만 허용 (e2e conftest 가 같은 트랜잭션에서 `SET LOCAL`).
- CHECK — 일정(`history_before = race_date − 1`, freeze_at = D−1 18:00 KST, `published_at` ∈ [freeze_at, deadline_at)),
  summary = payload->'summary', payload 해시, 공지 kind 별 edition_id 규칙, paused 의 `until`.
  감사 결과에 좌우되는 정책(무효·취소)은 CHECK 에 넣지 않았다 → 감사 뒤 037 로 제약을 다시 만들 일이 없다.
  반대로 CHECK 의 일정 값(H = D−1, 동결 18:00, 마감 상한 08:00)은 r1 정의(`history.offset_days`·`schedule.freeze_min`·
  `schedule.deadline_min`)와 겹친다 — 이 값을 바꾸는 새 버전은 마이그레이션도 함께 필요하다.
- 해시 — payload 해시는 INSERT 때 SQL 로만 계산하고(TS 는 계산하지 않음), 정의 해시는 Python 만 계산한다.
  두 방식을 섞어 재계산하지 않는다.
- **한계**: CHECK 는 잡이 넣은 `published_at` 만 본다. `created_at`(DB 시계)과의 차이·해시·트리거 상태는
  `racing-form-verify` 와 healthcheck 가 점검한다. 그래서 화면 문구도 "DB 가 거부"가 아니라
  "DB 보호 장치와 해시로 검증"이다.
- 함수 3개는 스키마를 붙이지 않는다 → prod(`mal_app`, search_path = mal, public)에서는 mal 스키마에 생겨
  `pg_dump -n mal` 백업에 포함된다 (확인 명령은 ⑨ 9.7).

### 9.4 정정·철회·미발행·쉼 절차

모든 공지는 `racing_form_notices` 에 **추가로만** 남는다. 발행본·예상·확정 정산은 어떤 경우에도 고치지 않는다.

**정정 (erratum)** — 발행본의 사실 오류(근거 숫자·소식 문장·입력 데이터)를 알린다.
1. 범위 확인: `racing-form-show` 로 발행본을 보고 `/races` 원본과 대조.
2. `racing-form-notice --kind erratum …` — 대상 호(경주일·경마장)와 공개 문구. 문구는 사실만 쓴다.
3. 1면 배너 + 그 호 경주면의 "이 호의 정정 n건" 블록 + 기록 페이지 발행 이력에 남는다 (경주면의 "이 경주의 발행 후
   변경" 에는 넣지 않는다 — 정정은 경주 범위가 없다). 예상·판정·집계는 그대로.
- 같은 문구는 dedup 으로 한 번만 들어간다. 잘못 쓴 정정은 지울 수 없으니 새 정정으로 바로잡는다.

**철회 (withdrawn)** — 호 전체가 잘못 나갔을 때 (가드가 못 잡은 버그, 잘못된 입력).
1. `racing-form-notice --kind withdrawn …` — 대상 호와 사유. CLI 가 "철회해도 집계에 포함됩니다"를 출력한다.
2. 화면: 예상은 그대로 + "철회됨 — 기록에 포함 ({시각}·{사유})" 배너, noindex.
   **법적 사유일 때만** `detail.hide_picks = true` 로 예상을 숨긴다 (집계는 유지).
3. 같은 (경주일, 경마장)은 다시 발행할 수 없다 (UNIQUE). 원인은 코드 수정·revert 로 고치고 다음 호부터 반영.

**미발행 (missed)** — 운영자가 따로 기록하지 않는다.
- 발행 잡이 D 08:00 실행에서 "출전표가 있는데 발행본 없음"을 확인하면 `missed` 공지 1건 + 잡 실패 1회(Telegram).
  웹은 공지가 없어도 마감이 지나면 "이번 호는 발행하지 않았습니다 — {사유 | 확인 중}".
- 운영자는 대시보드·Telegram·내부 `publish_failed` 공지(사유 코드)로 원인을 찾아 고친다.
  **수동 발행·늦은 발행 우회는 없다** — 마감 뒤 발행은 CHECK 가 거부한다. 고친 결과는 다음 호부터.
- 출시 전 호(freeze_at < 최초 rule_set 등록)와 쉼 기간은 missed 로 세지 않는다.

**쉼 (paused)** — 미리 정한 기간 발행하지 않을 때 (운영 점검, KRA 출전표 장애 장기화, 법률 검토 중 일시 중단 등).
1. `racing-form-notice --kind paused …` — 시작일·종료일(`detail.until`, 그날 포함)·경마장(생략 = 전체)·사유.
2. 잡은 그 기간 호를 발행하지도, missed 로 처리하지도 않는다. 웹 "이번 주는 쉽니다 — {사유}", 기록 페이지 호 수에 공개.
3. 공지는 추가 전용이라 등록한 기간을 줄일 수 없다 → **짧게(한 주 단위) 등록**하고 필요하면 이어서 다시 등록한다 (⑪ 11.4).

### 9.5 배포 금지 시간 — 목·금·토 17:30~18:15

- Jenkins 배포는 mal-crawler 컨테이너를 stop·rm 후 다시 올리고(`Jenkinsfile:120-142`), APScheduler 메모리 저장소는
  놓친 실행을 재생하지 않는다. 기동 직후 1회 실행으로 보완하지만, 18:00 발행과 배포가 겹치지 않게 한다.
- **PR-2 머지 이후 목·금·토 17:30~18:15 에는 main 에 push 하지 않는다** (금·토·일 경주의 D−1 18:00 발행).
  SCM 폴링이 `H/2` 라 17:58 push 도 18:00 전후 배포로 이어진다. PR-2 에서 deployment.md 에 함께 적는다.
- 놓쳐도 D 07:00 까지 매시 재시도하고, freeze + 60분을 넘긴 발행은 "늦게 발행"으로 표기된다.

### 9.6 롤백

- 웹: revert (페이지·링크 제거). 잡: revert (신규 발행만 중단 — 이미 나간 호·정산은 남는다).
- **마이그레이션은 되돌리지 않는다** — 기록 테이블은 추가 전용이고, 기록이 남아야 공개 원칙이 지켜진다.

### 9.7 prod 읽기 전용 감사·과거 시험 (사용자 작업, G1 전)

dev 에서는 prod 에 닿지 않는다(로컬 `DATABASE_URL` 은 localhost 만). healthcheck 와 같은 방식으로 운영자가
prod 호스트의 컨테이너 안에서 돌린다.

1. PR-1 배포 후 `ssh ... 'docker exec mal-crawler python -m src.main racing-form-preflight'` → 결과 공유.
2. 결과로 r1 정책을 사전 등록한다 — 작은 PR-1b (5.7 표, `definitions.py`, 해시 핀 갱신).
3. 비혼잡 시간(화 03:30 전후 — 02:30·03:00 야간 잡 뒤, 04:40 백업과 겹치지 않게)에
   `racing-form-backtest --from 2025-01-01 --to 2025-12-31 --label dev` → 후보 정의 해시 고정.
4. `racing-form-backtest --from 2026-01-01 --to 2026-10-31 --label holdout --save` **1회** — 이 명령만 prod 에 한 행을
   쓴다 (`racing_form_backtests`, 추가 전용). 한 호라도 실패하면(잠금·타임아웃·연결 끊김 등) 저장·출력 없이 exit 2 로
   멈춘다 — 1회를 쓰지 않았으니 원인을 확인하고 다시 실행한다.
5. 경주 주말에 1회 이상 D−1 18:05 에 `racing-form-build <D> <경마장> --json` dry-run → `/races` 와 대조.
6. preflight·dev·dry-run 은 prod 대신 백업 덤프를 임시 DB 에 복원해 돌려도 된다. 리허설 스크립트는 끝나면 DB 를

  무료·큰 글씨로 간다 (④ 4.1). 자체 점수(MSF)를 뺀 뒤에도 "골라 주는" 기능을 블랙박스 없이 제공한다.
